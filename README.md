# «Оглавление телеграм-канала» — готовый каталог постов

**Готовый набор файлов**: канал получает ОГЛАВЛЕНИЕ всех постов — каталог
с темами, поиском и датами, который открывается прямо в Telegram по кнопке.
Хостинг бесплатный навсегда (GitHub Pages), обновление оглавления —
автоматическое (GitHub Actions): новые посты канала сами долетают до каталога
~каждые 15 минут. Ни одного сервера арендовать не нужно.

- Цена комплекта: указана в боте при оплате (Telegram Stars), разово — без подписки
- Стоимость владения: **0 ₽/мес**
- Время настройки по гайду: **30–60 минут**

---

## Как это устроено

```
                    ВЛАДЕЛЕЦ КАНАЛА (один раз, ~40 минут)
     ┌──────────────────────────────────────────────────────────┐
     │  1. Репозиторий GitHub + файлы набора (drag & drop)      │
     │  2. Бот через BotFather (токен → в секреты GitHub)       │
     │  3. Канал → бот назначен админом (публикация постов)     │
     │  4. GitHub Pages включён (папка /docs)                   │
     │  5. config.js заполнен (канал + лицензионный ключ)       │
     └──────────────────────────────────────────────────────────┘
                              │
        ┌─────────────────────┴────────────────────┐
        ▼                                          ▼
  ИМПОРТ ВАШИХ ПОСТОВ                       САЙТ «ОГЛАВЛЕНИЕ»
  (публичный канал — авто из веб-превью;    (GitHub Pages, бесплатно)
  приватный — из экспорта Telegram)         темы · поиск · месяцы · алфавит
  оглавление строится ТОЛЬКО из ваших       · типы постов — на каждый пост
  постов — чужого контента не будет         кнопка «Оглавление» закреплена
                                            в шапке канала
```

Читатель открывает кнопку «Оглавление» в канале и видит каталог всех постов.
Кнопка ведёт на прямую ссылку Mini App (t.me/<бот>/<имя>) — каталог
разворачивается прямо в Telegram, на весь экран. Запасной вариант (если
конвейеру не передали прямую ссылку) — сайт оглавления: страница во
встроенном браузере, а на весь экран каталог открывает меню-кнопка (☰)
в чате с ботом — её настраивает конвейер «Кнопка оглавления» сам. Владелец
больше ничего не делает — всё работает само.

## Как собирается оглавление (4 уровня, от простого к умному)

1. **Всегда и без усилий — универсальные разделы.** Уже после первого импорта
   оглавление показывает карточки «📅 По месяцам», «🔤 По алфавиту» и
   «🎭 По типу постов» (тексты, фото, видео, аудио, опросы, файлы — типы
   определяются автоматически). Новости удобно листать по месяцам, блог —
   по алфавиту заголовков.
2. **Если в постах есть хэштеги — появятся ТЕМЫ.** Импорт собирает теги сам,
   а `pipeline/suggest_topics.py` превратит самые частые в карточки тем
   (бренд-теги отсекаются автоматически).
3. **Тегов нет, но хочется тем — ИИ за пределами продукта.**
   `pipeline/ai_tags.py --prepare` соберёт посты в готовый промпт: скопируйте
   его в любой чат-бот (ChatGPT/Claude/GigaChat), сохраните ответ и выполните
   `--apply` — теги расставлены, темы готовы. Продукт не платит за ИИ —
   владелец пользуется своим.
4. **Поиск и лента** работают всегда, поверх любых группировок.

## Два сценария использования

1. **Публичный канал (уже есть посты) — самый простой.** Запускаете действие
   «Импорт истории» (установщик делает это сам): посты собираются из
   веб-превью t.me/s/<канал> — оглавление наполнено сразу, без экспортов.
2. **Приватный канал.** Экспортируете канал через Telegram Desktop
   (`result.json`), кладёте файл в папку `import/`, запускаете «Импорт
   истории» — оглавление собрано по всему архиву.

Оглавление строится ТОЛЬКО из вашего контента: конвейеры набора не публикуют
в канал ничего постороннего — ни новостей, ни чужих постов.

## Быстрый старт (для нетерпеливых)

Полная версия — в `GUIDE.pdf`. Кратко:

1. Загрузите все файлы набора в свой новый репозиторий GitHub.
2. BotFather → `/newbot` → токен бота.
3. Канал → добавить бота админом (право «Публикация сообщений»).
4. Секреты репозитория: `BOT_TOKEN`, `CHANNEL_USERNAME`.
5. Settings → Pages → Branch `main`, папка `/docs`.
6. В `docs/config.js` впишите канал и лицензионный ключ.
7. Actions → «Кнопка оглавления» → Run → укажите адрес сайта (`pages_url`)
   и, если уже создали Mini App, прямую ссылку `t.me/<бот>/<имя>` (`app_link`)
   → пост с кнопкой закреплён в канале (с app_link — прямо в Telegram).
8. Actions → «Импорт истории» → Run → оглавление наполняют ВАШИ посты
   (публичный канал — автоматически; приватный — после экспорта в import/).

Дальше оглавление обновляется само: конвейер «Импорт истории» ходит по
расписанию (~каждые 15 минут), новые посты канала появляются в каталоге без
ваших действий. Ручной прогон остаётся: Run workflow — поле канала можно
оставить пустым. Нюанс GitHub: если в репозитории 60 дней не было ни одного
коммита, расписание засыпает — один ручной Run его будит.

## Если каталог отстал от канала (уснул GitHub)

Сайт оглавления работает всегда — он просто показывает то, что лежит в
`docs/posts.json`. А вот автоимпорт новых постов крутится на бесплатных
серверах GitHub, и у них есть правило экономии: **если в репозитории 60 дней
подряд не появилось ни одного сохранённого изменения (коммита), GitHub усыпляет
расписание** — «раз в проекте ничего не меняется, задачу можно не гонять».
Пауза касается только подхвата новых постов; сайт не гаснет никогда.

Хорошая новость: живой канал защищает себя сам. Каждый новый пост — это новое
сохранение: робот-импорт записал его в каталог и сделал коммит, счётчик
60 дней обнулился. Каналам, которые публикуют посты хотя бы раз в месяц-два,
засыпать просто не в чем.

Единственный неудобный случай: канал молчал два месяца и дольше, потом вышел
пост — расписание в этот момент спит, и пост сам не долетает. Узнать это легко:
новый пост в канале есть, а в каталоге его нет даже через полчаса.

**Как разбудить — одно нажатие, ~2 минуты:**

1. Открой свой репозиторий на GitHub (адрес — в памятке от бота).
2. Вкладка **Actions** — «пульт задач» (в шапке репозитория, рядом с Code).
3. В списке слева выбери задачу **«Импорт истории»**.
4. Справа серая кнопка **Run workflow**: поле канала оставь ПУСТЫМ (подставится
   само) и нажми зелёную **Run workflow**.
5. Через пару минут появится зелёная галочка: пост уже в каталоге, сайт
   пересобрался, расписание снова ходит само (~каждые 15 минут).

То же самое одним словом: напиши боту-установщику **«обнови оглавление»** —
он сам запустит импорт и разбудит расписание, ничего нажимать не нужно.

Каналам, публикующим хотя бы раз в месяц-два, всё это не грозит. Совсем тихим
каналам достаточно запускать «Импорт истории» кнопкой после каждого нового
поста — это тот же импорт, только по требованию.

## Обновления набора

Набор развивается, и обновления бесплатны: лицензия и ключ остаются прежними,
покупать комплект заново не нужно.

- **Рассылка.** Когда выходит новая версия, бот присылает покупателю два
  сообщения: сам архив и пошаговую инструкцию по замене файлов.
- **Самостоятельно.** Команда `/update` в чате с ботом присылает свежий архив
  в любой момент (ответ «У вас уже последняя версия» — норма: новых версий
  просто ещё не выходило). Обновление получает тот аккаунт Telegram, где была
  покупка.
- **Перед заменой файлов** сохраните свои `docs/config.js` (строки канала)
  и `docs/topics.json` — после заливки архива верните
  свои правки. Подробности — в `GUIDE.pdf`, раздел «Как получать обновления».


## Уведомления об обновлении оглавления

Когда в канале выходят новые посты и конвейер добавляет их в каталог, ваш бот
присылает вам в личку: «🔄 Оглавление обновлено: новых постов — N». Так же
работает и подписка «Оглавление» — поведение одинаковое в обоих вариантах.

Чтобы уведомления доходили:

1. В репозитории: Settings → Secrets and variables → Actions → New repository
   secret → имя `OWNER_TG_ID`, значение — ваш числовой id в Telegram
   (узнать можно у бота @userinfobot). Установщик («поехали») прописывает
   этот секрет сам — шаг нужен только при ручной установке.
2. Один раз нажмите Start в чате с ВАШИМ ботом (t.me/<имя_бота>): Telegram
   запрещает боту писать первым, без этого уведомления не дойдут.

Удалённые из канала посты исчезают из оглавления сами: при ближайшем
прогоне конвейер замечает пропажу, перепроверяет пост напрямую и убирает
его из каталога. Случайный сбой рендера историю не тронет — каждый
«пропавший» пост проверяется отдельно, массовая чистка за один прогон
невозможна.

Без секрета `OWNER_TG_ID` оглавление всё равно обновляется само — просто
без уведомлений. Нюанс GitHub: расписание означает «примерно каждые 15
минут» — слоты бывают заняты, задержка до получаса нормальна; если прогон
упал (например, t.me/s не открылся), GitHub пришлёт письмо на почту
владельца репозитория, а следующий прогон повторит импорт сам.

## Требования

- Аккаунт GitHub (бесплатный) и аккаунт Telegram.
- Канал должен иметь публичный @юзернейм (для ссылок на посты).
- Всё. Серверы, базы данных и оплата хостинга не нужны.
